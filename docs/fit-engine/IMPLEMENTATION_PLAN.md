### PR 0.2 · PubMed: MeSH, publication types, abstracts, author position
**Goal.** Stop discarding the highest-precision paradigm signal.
**Scale (counted 2026-09-05, after the PR 0.1b identity ladder).** 15,375 verified publication rows over 13,567 distinct PMIDs (1,808 rows are the same paper on several ImmunoX rosters); the earlier ~9,000 estimate is superseded. The backfill fetches by distinct PMID at 200 per efetch call, so a full pass is 68 calls at the 350 ms politeness interval, and every row sharing a PMID gets the same MeSH. It covers every verified row regardless of `identity_method` — `affiliation`, `orcid`, `profiles`, `reporter_link`, and the override / initials rungs, which write their rows as `affiliation` — so the selection carries no identity_method clause at all.
**Schema.** Migration `supabase/migrations/20260912100000_fit_pubmed_capture.sql`:

- New table `mesh_descriptors (ui TEXT PRIMARY KEY, name TEXT NOT NULL, tree_numbers TEXT[] NOT NULL, is_check_tag BOOLEAN NOT NULL DEFAULT false, year INTEGER NOT NULL)` with an index on `name`.
**Code.**
- `src/lib/community/pubmed-record.ts` (pure, unit-tested): parse `MeshHeadingList` (descriptor UI, name, `MajorTopicYN` on the descriptor or any qualifier, qualifier names), `PublicationTypeList`, `Abstract/AbstractText` (labeled sections joined as `LABEL: text`; `OtherAbstract` and the copyright line ignored), and the matched author's position — first / last / middle; `corresponding` when that author's affiliation carries the e-mail (PubMed's "Electronic address:" marker); co-first via `EqualContrib` counts as first; `unknown` when the investigator cannot be located on the list. The entry is located by the investigator's ORCID on the author entry when there is one (`author_position_method = 'orcid'`), else by name — strict name + UCSF affiliation first, then name-only for ORCID- and RePORTER-verified records (`'name'`; a common surname on a long author list is the Cho / Lee failure mode, so the method is stored) — else `'absent'`.
- `src/lib/community/pubmed-ingest.ts`: efetch is POSTed in batches (≤ 200); the identity ladder keeps the XML it fetched and the refresh fetches only what is still missing (ORCID hits), then stores the capture fields on upsert. Callers are unchanged. In-process records with no MeSH yet: store the abstract and publication types anyway, leave `mesh` empty, and set `mesh_fetched_at` so the backfill retries them after 30 days.
- `scripts/fit-backfill-pubmed-mesh.ts`: batch efetch (200 PMIDs per POST call, honor `NCBI_CONTACT_EMAIL`, ≥ 350 ms between calls) over publications where `identity_status = 'verified'` and `mesh_fetch_outcome = 'pending' OR (mesh_fetch_outcome IN ('no_mesh','not_returned') AND mesh_fetched_at < now() - interval '30 days')`; deduplicates PMIDs across investigators and writes to every row sharing one; records `mesh_fetched_at` and `mesh_fetch_outcome` for **every PMID it touches** — `indexed`, `no_mesh` (returned without MeSH, in-process), `not_returned` — so a rerun is resumable and never re-fetches the corpus. A PMID efetch does not return — confirmed by the PR 0.2a targeted retry — is `not_returned` once and **`not_returned_terminal` on the second miss** — it is a bad linkage or a withdrawn record, not an in-process one, and is never re-requested. `--report` writes rows by outcome and the terminal PMIDs (a PMID we hold that PubMed does not have deserves a person's eyes) to `INVENTORY.md` § 11. `--dry-run`, `--limit`, `--investigator <id>`, `--pmid <list>` (`--force` re-fetches listed PMIDs even if stamped — after a parser fix). Prints the pending-row count and the expected number of efetch calls before fetching.
- `scripts/fit-load-mesh-descriptors.ts`: download the current NLM descriptor file (D10; `desc<year>.gz`, ~17 MB, streamed), parse `DescriptorUI`, `DescriptorName`, `TreeNumberList`, and load `mesh_descriptors`; mark check tags from an explicit list (NLM's `DescriptorClass` flags only Male and Female, so it cannot be used). Then **validate `src/lib/fit/signal-mapping.json` against the loaded table** — every `mesh*`, `check_tag*` and `pubtype*` name and every `mesh_tree_under*` / `triangle_of_biomedicine` prefix — and exit non-zero listing each unmatched value with the rule ids that would go dark. `--validate-only` re-runs the check against the table without downloading; `--write-fixture` writes the descriptor subset the unit tests use.
- `src/lib/fit/classify/mesh.ts`: `buildMeshIndex(rows)`, `resolveDescriptor(nameOrUi)`, `treeNumbers(ui)`, `isUnder(ui, prefix)`, `triangleClass(uis)` per `signal-mapping.json › triangle_of_biomedicine` — Humans matched by **UI** (`human_uis`), subtrees by prefix (D12) — and `validateSignalMapping(index)` over names, UIs and prefixes. Unit tests with a fixture subset generated from the real file, including one that asserts every name in `signal-mapping.json` is present in the fixture — so a mapping edit without a regenerated fixture fails CI.
**Acceptance.** (1) Backfill dry-run on 20 real PMIDs prints MeSH names and pub types that match PubMed's web view for 3 spot-checked records; (2) `resolveDescriptor` fails loudly on an unknown name; (3) after the descriptor table loads, every MeSH name, UI and tree prefix used as a key in `signal-mapping.json` resolves — the loader fails with the list of unmatched values otherwise (23 of 70 rules have MeSH names as their only `when` signal and would go dark with no signal that they had), and the check runs on **every** descriptor reload, not only the first, and in CI against the fixture (D12); (4) `mesh_fetched_at` and `mesh_fetch_outcome` are set for every PMID the backfill touched, including no-MeSH and not-returned ones, and a second run fetches nothing; (5) a PMID not returned twice is `not_returned_terminal`, never re-requested, and listed in `INVENTORY.md` § 11 by `--report`; (6) `author_position_method` is stored alongside every `author_position`; (7) tests green, tsc clean.

### PR 0.2a · Confirm a miss before stamping `not_returned`
**Why.** A partial efetch response under load — 200 asked, 100 returned, HTTP 200 — would stamp 100 real publications `not_returned` in one call, and a second hiccup 30 days later would make them `not_returned_terminal`. The first run's stamps have to be trustworthy or run two's terminal marks are not. Found 2026-09-05 from a 2-requested / 1-returned curl during the PR 0.2 dry run.
**Rule.** PMIDs absent from a batch response are re-requested once, in one call, together with a **canary** — a PMID this run already received. The retry returning nothing (canary included) is the service failing, not the data: nothing is stamped, the run exits 2 and prints the batch index and the resume point (a rerun of the same command; earlier batches are stamped and skipped). The retry returning anything proves the service healthy, so what is still missing is a real absence and is stamped — unless more than 25 are still missing in one batch, which aborts the same way (that many dead PMIDs in one 200-batch is not a plausible corpus). `decideBatchMisses` in `pubmed-mesh-backfill.ts` is pure and unit-tested; the script wires it before any write.
**Acceptance.** Tests for: no misses; isolated miss with canary-only retry (stamped); hiccup partially recovered (only the rest stamped); retry returns nothing (abort, nothing stamped); 26 still missing (abort), 25 (stamped). Dry run prints per-batch first-response / re-requested / recovered / confirmed-absent counts. Lands before the first real backfill run.

### PR 0.3 · ClinicalTrials.gov: design fields and investigator role
**Schema.** `investigator_clinical_trials` + `study_type TEXT`, `phases TEXT[]`, `primary_purpose TEXT`, `allocation TEXT`, `intervention_model TEXT`, `observational_model TEXT`, `time_perspective TEXT`, `enrollment INTEGER`, `intervention_types TEXT[]`, `investigator_role TEXT` (PRINCIPAL_INVESTIGATOR | STUDY_CHAIR | STUDY_DIRECTOR | RESPONSIBLE_PARTY_PI | LISTED | UNKNOWN), `design_parsed_at TIMESTAMPTZ`.

Call it from `refreshInvestigatorClinicalTrials` on upsert. `scripts/fit-backfill-ctgov-design.ts`: parse from stored `raw_json` for all rows (no network), idempotent.
**Rules (implemented 2026-09-05).** Migration `supabase/migrations/20260913110000_fit_ctgov_design.sql`; `investigator_role` carries the CHECK constraint, `phases` and `intervention_types` are `NOT NULL DEFAULT '{}'`, everything else nullable — NULL `study_type` / `investigator_role` with `design_parsed_at IS NULL` means *not parsed yet*; a parsed record with nothing to read stores NULLs, `{}` and `UNKNOWN` with the stamp set. Enums are stored as CT.gov spells them (case and separators folded, `N/A` → `NA`; classic-API labels are not remapped — every row came from v2) because the ctgov rules in `signal-mapping.json` key on those strings. **Role precedence** when a record names the person in several places is the enum order: `PRINCIPAL_INVESTIGATOR` > `STUDY_CHAIR` > `STUDY_DIRECTOR` (from `overallOfficials[].role` on the matching entry) > `RESPONSIBLE_PARTY_PI` (`responsibleParty.type` PRINCIPAL_INVESTIGATOR or SPONSOR_INVESTIGATOR with a matching `investigatorFullName`); the classifier treats all four alike (`investigator_role_any`), so the order only affects the stored label. `LISTED` = the record names officials or a responsible-party investigator and this person is not among them in a recognised role (a matched official with a missing role is also `LISTED`); `UNKNOWN` = nothing to match against (no `protocolSection`, no officials and no responsible-party investigator, or no name to look for). The name test is the ingest's own (`personNameMatches`, extracted from `studyMatchesInvestigatorName`: equal after folding, or one contains the other), so a middle initial on one side only — "Susan M. Chang, MD" vs roster "Susan Chang" — misses on the official and is recovered through `responsibleParty` when the person is the responsible party. `phases = ["NA"]` is stored literally; `phasesAreInformative(phases)` is false for `[]` and `["NA"]` so PR 1.2 reads `allocation` / `intervention_model` for those instead of the phase (`signal-mapping.json` has no clause for either yet — see the follow-up below). The ingest stores the fields on every upsert via `designCaptureFields`; **apply the migration before deploying the ingest change** — an upsert against the old schema fails on the unknown columns and `refreshInvestigatorClinicalTrials` counts it as not inserted. `scripts/fit-backfill-ctgov-design.ts` (`npm run fit:backfill-ctgov-design`): parses every row's `raw_json`, `--dry-run` prints each row as it would be stored plus the coverage line, `--pending` restricts to `design_parsed_at IS NULL`, `--limit`, `--investigator`, `--nct`; upserts on `(investigator_id, nct_id)` in chunks of 200.
**Acceptance.** Backfill over existing rows fills `study_type` for ≥ 95% of rows that have a `protocolSection`; unit tests on 4 fixture study records (interventional phase 2 with PI role; observational cohort; interventional without role; interventional with `phases = ["NA"]` and a randomized parallel design), plus role precedence, the middle-initial recovery, enum folding and a record with no `protocolSection`.

## Working with Claude Code on this plan

**Operating model (2026-09-05).** One builder agent per PR, working architect + builder + scribe as a single loop in its own git worktree under `/tmp` branched from `origin/main` (the main checkout is never switched). An independent validator agent reviews each branch cold — plan section, acceptance criteria, tests, tsc, dry run, diff — before the PR opens. Disjoint Phase 0 items are built in parallel worktrees and merged in sequence; Phase 1 onward is sequential. Standing authorizations: PRs merge after CI and the validator are green (worktree removed first, `gh pr list --base <branch>` empty, squash, `--delete-branch`, remote ref verified gone); migrations are applied by the coordinator; backfills and loads run without asking once their dry run is clean, with the first run of each split (`--limit` one batch, stored rows inspected, then the rest). Landing sequence per PR: validator → PR → CI green → rebase the branch onto `origin/main` (its migrations directory must hold every migration the remote already has, or the CLI refuses; `package.json` `fit:*` aliases from parallel builders conflict there and are resolved as the union of both `scripts` maps) → `supabase db push` from that worktree, dry-run listing exactly the PR's file, **before** the merge (Vercel deploys `main` on merge and an ingest writing new columns fails silently until the migration lands) → remove the PR's worktrees → squash-merge with `--delete-branch` → verify the remote ref is gone → real backfill, first run split.
